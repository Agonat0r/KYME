# KYMA Current Workflow Guide

This guide matches the current KYMA workflow: live electrodes or uploaded datasets become saved projects, rebuild jobs, reports, and export packages through the prompt pipeline.

## Product Loop

1. Choose the source.
   - Live electrodes for real-time EMG, EEG, ECG, EOG, PPG, EDA, respiration, temperature, or mixed streams.
   - Synthetic demo only when you want KYMA to simulate the collection/training path without real electrodes.
   - Dataset path for CSV, NPZ, EDF/BDF, XDF, MAT, WAV, HDF5, Parquet, or KYMA session folders.
   - Synthetic or playback when testing the UI, model loop, or previous sessions.
2. Open Dashboard and verify the stream.
   - Confirm channel count, sample rate, units, signal amplitude, clipping, and channel health.
   - Use freeze, markers, and Workshop when a region needs deeper DSP review.
3. Open Build and describe the goal.
   - Example: `Build an EMG pinch classifier from this EDF file.`
   - Example: `Create an EOG blink detector from this XDF session and export a report.`
   - Example: `Make a fatigue review model from these labeled CSV windows.`
4. Build automatically first.
   - Click `Build Automatically` unless you deliberately want manual control.
   - Autopilot runs the best available sequence: Generate Plan, Import or QA, Ingest or acquisition setup, Train when possible, Export, Save, and Projects.
   - If live electrode data is needed, Autopilot opens the setup flow, tells the user to connect electrodes, shows the tasks to perform, and waits for `I Am Ready - Start Tasks`.
   - If the signal or task data is bad, Autopilot asks the user to fix the setup and retry instead of training on weak data.
5. Train or rebuild.
   - Use Train Baseline for a quick local model.
   - Use Train Auto when guided acquisition or current project state has enough windows.
   - Use Rebuild from the project registry when repeating a saved project recipe.
6. Review artifacts.
   - Open Report for the dataset, recipe, QA, model, and export summary.
   - Download Package for the export bundle.
   - Compare projects and jobs before routing anything to live control or firmware.

## Build Panel Buttons

| Button | What It Does | Use It When |
| --- | --- | --- |
| Build Automatically | Runs the source -> plan -> inspect/QA -> ingest/acquire -> train -> export -> save workflow and shows the next action. Live electrodes always opens setup/tasks first; Synthetic demo can auto-complete. | Use this first for almost every prompt. |
| Create Model | Runs the fastest prompt-to-model path from current context. | You want an automated baseline. |
| Generate Plan | Creates a visible recipe with source, cleanup, labels, model, validation, and export steps. | You want to inspect before training. |
| Import | Reads a dataset and detects channels, labels, sample rate, and supported format. | You have a file or session path. |
| Ingest | Saves imported data as a KYMA project. | The detected dataset looks correct. |
| Run QA | Checks channel health, artifacts, balance, and training readiness. | Before training or exporting. |
| Train Baseline | Fits a baseline model from available windows and labels. | You need a quick model result. |
| Train Auto | Runs the guided acquisition/training path. | You are using live or staged acquisition. |
| Projects | Opens the searchable project/job registry. | You need saved projects, rebuilds, reports, or packages. |

## Project Registry

The project registry is the current workspace for saved datasets and jobs.

Use search for:
- project name
- label names
- file path
- format
- status
- job id

Use filters for:
- project/job status
- data format

Project actions:
- `Load`: restore a project in the Build panel.
- `Rebuild`: start a background rebuild job from the saved project.
- `Open Report`: open the project markdown report.
- `Copy Report`: copy the report path.
- `Download Package`: create and download a ZIP from the export directory.
- `Copy Package`: copy the export path.
- `Delete`: remove the project entry.

Rebuild job actions:
- `Details`: load the job result and logs into the preview.
- `Open Report`: open the rebuild job report.
- `Copy Report`: copy the rebuild report path.
- `Download Package`: download the export bundle generated by the job.
- `Copy Package`: copy the export path.
- `Delete Job`: remove the job record.

## Reports And Packages

Project reports should answer:
- What source was used?
- Which format was imported?
- How many channels and windows were detected?
- Which labels/classes exist?
- Which recipe was used?
- What QA warnings exist?
- Which model or export artifacts were produced?

Rebuild reports should answer:
- Which project was rebuilt?
- Which steps ran?
- Which step failed, if any?
- Where are the artifacts?
- Is the result ready for review, training, or deployment?

Packages should carry the handoff bundle for notebooks, team review, model deployment, or archival.

## Live AI And ML Review

Use AI and ML outputs as workflow assistants:
- highlight detected signal regions
- explain signal spans on hover
- flag bad electrodes, clipping, drift, and noise
- show predicted class and confidence
- suggest cleanup, label, acquisition, and model actions

Do not treat live AI output as final evidence until the source data, labels, QA, recipe, and model metrics are saved.

## Live Electrode Autopilot

When the source is live electrodes, Autopilot should run as a guided collection flow:

1. Create the recipe.
2. Open the stream/channel setup area.
3. Tell the user to connect electrodes and check channel activity.
4. Show the task list, such as rest baseline, fresh contraction, fatiguing contraction, and recovery.
5. Wait for `I Am Ready - Start Tasks`.
6. Record each task through the acquisition QA gate.
7. Reject bad windows automatically.
8. If too much data is rejected, ask the user to fix electrodes or repeat the movement and retry.
9. If enough clean windows are accepted, train the model, export the package, and save the report.

## Control And Firmware

Use control outputs after the biosignal path is stable.

Recommended order:
1. Validate source data and labels.
2. Train or load a model.
3. Confirm live prediction quality.
4. Map labels or metrics to Control actions.
5. Use Blocks for graph logic or generated `.ino` sketches.
6. Use Firmware for editing, compile checks, and upload.

Hardware is one output target. KYMA should also support software models, analysis reports, dataset packages, runtime configs, and deployment bundles.

## Current Definition Of Done

A KYMA workflow is complete when it has:
- a saved project
- a visible recipe
- source metadata
- labels or acquisition protocol
- QA result
- model or explicit reason training was blocked
- report
- package/export directory
- rebuild job history when repeated
