Guide

KYMA Workflow Guide

Use this path when you want to go from live electrodes or a dataset to a cleaned biosignal project, trainable model, report, and export package.

Current Product Loop

  1. Pick a signal source: live hardware, synthetic stream, playback, LSL, OSC, serial, or an uploaded dataset.
  2. Open Dashboard, choose the signal profile, and verify channel count, sample rate, units, and visible signal quality.
  3. Open Build and describe the goal, such as Build an EMG pinch classifier from this EDF file.
  4. Click Build Automatically first. KYMA will plan, inspect or QA, ingest or prepare labels, train when possible, export, save, and show the next action.
  5. For live electrodes, Autopilot opens the setup path, asks you to connect electrodes, shows task prompts, rejects bad windows, and asks for retry when the signal is weak.
  6. Use Train Baseline, Train Auto, or a rebuild job to create a model from the saved project.
  7. Review the project registry, open the report, and download the package for the dataset, recipe, model, and run summary.
The goal is prompt-to-pipeline: KYMA should do the automatic work first, while leaving every recipe, label, metric, model, and export visible enough to trust.

Project Registry

The registry is the control room for saved datasets and rebuild jobs. Search by label, project name, path, format, status, or job id. Filter by status and format when the workspace gets crowded.

  1. Load reopens a project in the Build panel.
  2. Rebuild starts a background job from the saved recipe and dataset.
  3. Open Report opens the project or job markdown report in the browser.
  4. Copy Report copies the report path for notebooks, commits, or sharing.
  5. Download Package creates a ZIP containing the export bundle.
  6. Copy Package copies the export directory or package path.
A highlighted metric or model result is only useful if the source data, labels, and recipe are saved. Use Save or Ingest before treating a run as reproducible.

Live AI And ML Review

Use the AI lens and live ML outputs as review assistants. They should point at channels, signal spans, likely artifacts, predicted classes, and data-quality problems. Treat those outputs as workflow guidance until the run has a saved dataset, labels, QA, and validation metrics.

Review SignalWhat To Look ForAction
Persistent highlightsDetected class, artifact, fatigue, onset, or suspicious region.Hover for details, then freeze or mark the span.
Channel QABad electrodes, clipping, noise, drift, low amplitude, or missing channels.Fix the setup or add a cleanup step to the recipe.
Prediction outputLabel and confidence from the active model.Compare against expected labels before routing to control.
Data balanceEnough clean windows per class.Acquire or label more examples before training.

Control, Blocks, And Firmware

After the signal path is stable, use Control, Blocks, and Firmware for outputs. Do this after validation, not before.

  1. Use Control to map decoded labels or metrics to live actions.
  2. Use Blocks for graph logic, servo moves, loops, conditionals, and generated sketches.
  3. Use Filters when the live signal needs a reusable host-side DSP stage.
  4. Use Firmware when generated Arduino code needs editing, compile checks, or upload.
Hardware control is now one output target. The same pipeline can also produce software classifiers, reports, dataset packages, and runtime model configs.
